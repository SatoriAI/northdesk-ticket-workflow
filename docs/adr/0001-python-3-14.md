# 0001. Run on Python 3.14

Status: accepted, 2026-10-28

## Context

The service needs a Python version that `temporalio`, FastAPI, pydantic and the Temporal
time-skipping test server all support. The newest stable release is 3.14, and a newer version is
preferred when every dependency supports it. Temporal's workflow
sandbox re-imports workflow modules with a custom importer, which is the part most likely to break
on a new interpreter.

## Decision

Use Python 3.14 everywhere: `requires-python`, `.python-version` and the Docker base image.

## Evidence

Before writing any service code, a throwaway script on CPython 3.14.2 with `temporalio` 1.34.0 did
three things. It ran a workflow in the sandbox. It ran `WorkflowEnvironment.start_time_skipping()`,
where a 24 h `workflow.wait_condition` timed out in seconds. It sent a Workflow Update to the
`start_local()` dev server and got the result back.

## Consequences

If a dependency drops 3.14 support or the sandbox breaks, the fallback is 3.13. That is more than
changing `requires-python`, `.python-version` and the Dockerfile `FROM`. The code relies on 3.14's
deferred evaluation of annotations (PEP 649): `DataRepository.load() -> DataRepository` names the class
inside its own body, which raises `NameError` on 3.13. Modules like that would need
`from __future__ import annotations`, and ruff's target version would have to move to 3.13 so that
UP037 stops removing the quotes it would otherwise need.
